📖 Theory

Mathematical Foundations of Elliptic Curve Cryptography & ECDH Protocol

SUBSECTION A

A. Elliptic Curve Cryptography

Elliptic Curve Cryptography (ECC) is a public-key cryptographic technique based on mathematical operations over points on an elliptic curve defined over a finite field.

General Weierstrass Equation over Prime Finite Field \(\mathbb{F}_p\):
\[y^2 \equiv x^3 + ax + b \pmod{p}\]

Curve Parameters & Components:

  • \(a\) and \(b\): Curve parameters (coefficients) that define the specific elliptic curve equation.
  • \(p\): The prime integer defining the finite field \(\mathbb{F}_p = \{0, 1, 2, \dots, p-1\}\) over which all arithmetic is performed modulo \(p\).
  • Points on the Curve: Pairs of coordinates \((x, y)\) satisfying the modular equation belong to the curve, along with the special identity element known as the Point at Infinity (\(\mathcal{O}\)).
  • Generator / Base Point (\(G\)): A publicly known generator/base point \(G = (G_x, G_y)\) selected on the curve to generate a large cyclic subgroup of points for cryptographic operations.
  • Non-Singularity Condition: To ensure the curve is smooth with well-defined tangent lines at every point, the discriminant must satisfy: \[\Delta = 4a^3 + 27b^2 \not\equiv 0 \pmod{p}\]
SUBSECTION B

B. Point Addition & Point Doubling

Two points on an elliptic curve can be combined algebraically to produce another point on the curve. This forms an abelian group structure:

\[P + Q = R\]

1. Point Addition (\(P \ne Q\))

When adding two distinct points \(P = (x_1, y_1)\) and \(Q = (x_2, y_2)\) where \(x_1 \ne x_2\), the slope \(m\) of the line through \(P\) and \(Q\) is:

\[m = \frac{y_2 - y_1}{x_2 - x_1} \pmod{p}\]

The resulting point coordinates \(R = (x_3, y_3)\) are computed as:

\[x_3 = (m^2 - x_1 - x_2) \pmod{p}\] \[y_3 = (m(x_1 - x_3) - y_1) \pmod{p}\]

2. Point Doubling (\(P + P = 2P\))

When adding a point to itself (\(P = Q\)), the slope \(m\) is the tangent to the curve at \((x_1, y_1)\):

\[m = \frac{3x_1^2 + a}{2y_1} \pmod{p}\]

The resulting doubled point coordinates \(2P = (x_3, y_3)\) are:

\[x_3 = (m^2 - 2x_1) \pmod{p}\] \[y_3 = (m(x_1 - x_3) - y_1) \pmod{p}\]
Point at Infinity (\(\mathcal{O}\)): The additive identity element satisfying \(P + \mathcal{O} = P\) and \(P + (-P) = \mathcal{O}\) for all curve points \(P\).
SUBSECTION C

C. Scalar Multiplication & Discrete Logarithm Problem

Scalar multiplication combines a point \(G\) with an integer scalar \(k\) by repeated addition:

\[kG = \underbrace{G + G + G + \dots + G}_{k \text{ times}}\]

Efficiency of Computation

Scalar multiplication is computed in \(\mathcal{O}(\log_2 k)\) operations using the Double-and-Add Algorithm (the binary expansion of \(k\)). This makes computing public keys \(kG\) extremely fast even for large private keys.

Elliptic Curve Discrete Logarithm Problem (ECDLP)

While scalar multiplication \(kG\) is easy to compute, reversing it—determining the scalar \(k\) given base point \(G\) and public point \(P = kG\)—is computationally infeasible for appropriately chosen parameters. This one-way asymmetry is the Elliptic Curve Discrete Logarithm Problem (ECDLP) and serves as the security foundation of ECC.

SUBSECTION D

D. Elliptic Curve Diffie-Hellman (ECDH) Key Exchange

The ECDH protocol allows two communicating parties (Alice and Bob) to independently compute a shared cryptographic secret:

👩‍💻

Alice

Alice selects private key \(a\) (secret).

Alice calculates public key:

\[A = aG\]

Alice receives Bob's public key \(B\) and computes:

\[S = aB\]
PUBLIC NETWORK CHANNEL
Alice transmits Public Key \(A \longrightarrow\) Bob
Alice \(\longleftarrow\) Bob transmits Public Key \(B\)
Only Public Keys \(A\) and \(B\) cross the channel!
👨‍💻

Bob

Bob selects private key \(b\) (secret).

Bob calculates public key:

\[B = bG\]

Bob receives Alice's public key \(A\) and computes:

\[S = bA\]

Derivation of the Shared Secret:

\[S = aB = a(bG) = b(aG) = bA = abG\]

Thus both parties obtain the same shared secret point \(S\) independently on their local machines.

🛡️

CRITICAL SECURITY INVARIANT:

PRIVATE KEYS NEVER TRAVEL THROUGH THE NETWORK.

Only public keys \(A\) and \(B\) are exchanged. An eavesdropper intercepting the transmission cannot determine \(a\) or \(b\) due to the discrete logarithm problem, and therefore cannot derive the shared secret \(S = abG\).

📖 ECC & ECDH Concepts

Mathematical Foundations of Elliptic Curve Cryptography

01

What is Elliptic Curve Cryptography (ECC)?

ECC is an asymmetric public-key cryptosystem based on the algebraic structure of elliptic curves over finite fields. Its primary security relies on the Elliptic Curve Discrete Logarithm Problem (ECDLP): given a base point \(G\) and a public point \(P = k \cdot G\), it is computationally infeasible to determine the secret scalar \(k\).

Key Advantage: Equivalent security to RSA with significantly smaller keys (e.g. 256-bit ECC \(\approx\) 3072-bit RSA).
02

The Elliptic Curve Equation

In our simulator, we use the standard Weierstrass Equation over a prime finite field \(\mathbb{F}_p\):

\[y^2 \equiv x^3 + ax + b \pmod{p}\]

To ensure the curve has no cusps, self-intersections, or singular points, the discriminant must satisfy:

\[\Delta = 4a^3 + 27b^2 \not\equiv 0 \pmod{p}\]
03

What is a Finite Field (\(\mathbb{F}_p\))?

Instead of smooth, continuous real numbers \(\mathbb{R}\), finite field cryptography uses modular arithmetic over integers modulo a prime \(p\): \(\{0, 1, 2, \dots, p-1\}\).

Division in \(\mathbb{F}_p\) is accomplished by computing the modular multiplicative inverse using Fermat's Little Theorem or the Extended Euclidean Algorithm:

\[\frac{1}{d} \equiv d^{-1} \equiv d^{p-2} \pmod{p}\]
04

Point on a Curve & Point at Infinity

A point \(P = (x, y)\) is a valid point if its coordinates satisfy \((y^2 - (x^3 + ax + b)) \bmod p = 0\).

The curve also includes a special identity element called the Point at Infinity (\(\mathcal{O}\)), which acts like zero in regular addition:

\[P + \mathcal{O} = P \quad \text{and} \quad P + (-P) = \mathcal{O}\]
05

Point Addition (\(P + Q = R\), \(P \ne Q\))

To add two distinct points \(P = (x_1, y_1)\) and \(Q = (x_2, y_2)\) where \(x_1 \ne x_2\):

\[m = \frac{y_2 - y_1}{x_2 - x_1} \pmod{p}\] \[x_3 = (m^2 - x_1 - x_2) \pmod{p}\] \[y_3 = (m(x_1 - x_3) - y_1) \pmod{p}\]
06

Point Doubling (\(P + P = 2P\))

When adding a point to itself (\(P = Q\)), the slope is the tangent to the curve at \((x_1, y_1)\):

\[m = \frac{3x_1^2 + a}{2y_1} \pmod{p}\] \[x_3 = (m^2 - 2x_1) \pmod{p}\] \[y_3 = (m(x_1 - x_3) - y_1) \pmod{p}\]
07

Scalar Multiplication (\(k \cdot P\))

Scalar multiplication computes \(k \cdot P = \underbrace{P + P + \dots + P}_{k \text{ times}}\).

Using the Double-and-Add Algorithm (binary method), scalar multiplication runs in logarithmic \(O(\log k)\) steps instead of linear time: 

result = None
while k > 0:
    if k % 2 == 1:
        result = point_add(result, P)
    P = point_add(P, P)  # Point doubling
    k = k // 2
08

Elliptic Curve Diffie-Hellman (ECDH) Protocol

ECDH allows two parties (Alice and Bob) to establish a shared cryptographic key over an insecure public channel without transmitting the secret:

👩‍💻 Alice

Private Key: \(d_A\) (secret)

Public Key: \(A = d_A \cdot G\)

Sends \(A \to\) Bob
Calculates:
\[S_{\text{Alice}} = d_A \cdot B = d_A \cdot (d_B \cdot G)\]
Public Channel ⇄ Transmits \(A\) and \(B\)
\[d_A \cdot d_B \cdot G = d_B \cdot d_A \cdot G\] Shared Secret is Identical!

👨‍💻 Bob

Private Key: \(d_B\) (secret)

Public Key: \(B = d_B \cdot G\)

Sends \(B \to\) Alice
Calculates:
\[S_{\text{Bob}} = d_B \cdot A = d_B \cdot (d_A \cdot G)\]

Q01 Theory & Overview

What is Elliptic Curve Cryptography?

Model Answer:

Elliptic Curve Cryptography (ECC) is an asymmetric public-key cryptosystem based on the algebraic structure of elliptic curves defined over finite fields (such as \(\mathbb{F}_p\) for prime \(p\)). Unlike traditional public-key schemes such as RSA which rely on large prime factorization, ECC bases its security on the hardness of the Elliptic Curve Discrete Logarithm Problem (ECDLP).

Key Advantage: ECC achieves equivalent cryptographic strength with substantially smaller key sizes (e.g., a 256-bit ECC key offers approximately the same security as a 3072-bit RSA key), leading to faster computation, reduced memory footprint, and lower network transmission energy.

Q02 Curve Parameters

What is the role of a generator point in ECC?

Model Answer:

A generator point (or base point) \(G = (G_x, G_y)\) is a publicly known fixed point on the elliptic curve that generates a large cyclic subgroup of curve points through repeated scalar multiplication: \(\{G, 2G, 3G, \dots, nG = \mathcal{O}\}\), where \(n\) is the order of the subgroup.

In cryptographic protocols like ECDH, all public keys are computed as scalar multiples of this common base point: \(P = d \cdot G\). Because \(G\) is fixed and standardized (e.g., in NIST or SECG standards), both communicating parties and any third-party verifier can perform calculations in the identical mathematical subgroup.

Q03 Point Operations

Explain elliptic-curve point addition.

Model Answer:

Given two distinct points \(P = (x_1, y_1)\) and \(Q = (x_2, y_2)\) on an elliptic curve over \(\mathbb{F}_p\) with \(x_1 \ne x_2\), their sum \(R = P + Q = (x_3, y_3)\) is computed by drawing a secant line through \(P\) and \(Q\), finding the third point of intersection with the curve, and reflecting that point across the x-axis:

Slope \(m\): \(m \equiv \frac{y_2 - y_1}{x_2 - x_1} \pmod{p}\)
Coordinates:
\(x_3 \equiv (m^2 - x_1 - x_2) \pmod{p}\)
\(y_3 \equiv (m(x_1 - x_3) - y_1) \pmod{p}\)

Division modulo \(p\) is accomplished by multiplying with the modular multiplicative inverse: \((x_2 - x_1)^{-1} \pmod{p}\). If \(P = Q\), point doubling is used instead with the tangent slope.

Q04 Scalar Multiplication

What is scalar multiplication in ECC?

Model Answer:

Scalar multiplication in ECC is the operation of adding a curve point \(P\) to itself \(k\) times, denoted as: \[kP = \underbrace{P + P + \dots + P}_{k \text{ times}}\] where \(k\) is an integer scalar.

To compute this efficiently without performing \(k-1\) sequential additions, the Double-and-Add Algorithm is used. It scans the binary representation of \(k\) from most significant to least significant bit, doubling the accumulator point at each bit position and adding \(P\) whenever a bit is '1'. This reduces the computational complexity from linear \(\mathcal{O}(k)\) to logarithmic \(\mathcal{O}(\log_2 k)\).

Q05 Protocol Execution

Explain the ECDH key exchange process.

Model Answer:

The Elliptic Curve Diffie-Hellman (ECDH) protocol executes as follows:

  1. Setup: Alice and Bob agree on public domain parameters: curve equation \(y^2 \equiv x^3 + ax + b \pmod p\) and base generator point \(G\).
  2. Alice Keygen: Alice chooses private scalar \(a\) and calculates public point \(A = aG\).
  3. Bob Keygen: Bob chooses private scalar \(b\) and calculates public point \(B = bG\).
  4. Key Exchange: Alice and Bob send public points \(A\) and \(B\) to each other over the public network.
  5. Shared Secret Derivation: Alice calculates \(S = aB\). Bob calculates \(S = bA\).
  6. Agreement: Both obtain \(S = a(bG) = b(aG) = abG\), which is used as a symmetric encryption key.
Q06 Security & Confidentiality

Why are private keys not transmitted during ECDH?

Model Answer:

The foundational premise of asymmetric key agreement is that the communication medium is insecure and subject to eavesdropping. If private scalars \(a\) or \(b\) were transmitted across the channel, an adversary intercepting the traffic could immediately compute the shared secret \(S = abG\) and decrypt all subsequent confidential communications.

By transmitting only public points \(A = aG\) and \(B = bG\), the private keys remain strictly confined to the local memory of the participants. The adversary is faced with the Computational Diffie-Hellman Problem (CDHP) and ECDLP, which cannot be solved in polynomial time for cryptographically secure curves.

Q07 Mathematical Identity

How are Alice and Bob able to derive the same shared secret?

Model Answer:

Alice and Bob derive identical shared secrets due to the associative and commutative properties of scalar multiplication in the elliptic curve abelian point group:

\[S_{\text{Alice}} = a \cdot B = a \cdot (b \cdot G) = (a \cdot b) \cdot G\] \[S_{\text{Bob}} = b \cdot A = b \cdot (a \cdot G) = (b \cdot a) \cdot G\]

Since integer scalar multiplication is commutative (\(a \cdot b = b \cdot a\)), both computations yield the exact same point: \[(a \cdot b) \cdot G = (b \cdot a) \cdot G = abG = S\]

Q08 Computational Hardness

What is the elliptic curve discrete logarithm problem?

Model Answer:

The Elliptic Curve Discrete Logarithm Problem (ECDLP) is stated as:

Given an elliptic curve over a finite field \(\mathbb{F}_p\), a generator point \(G\) of order \(n\), and a point \(Q\) in the subgroup generated by \(G\), find the unique integer scalar \(k \in [1, n-1]\) such that: \[Q = k \cdot G\]

While forward scalar multiplication is easily computable in \(\mathcal{O}(\log k)\) operations, solving for \(k\) requires exponential time using generic algorithms like Pollard's rho method (\(\mathcal{O}(\sqrt{n})\)). No known sub-exponential algorithm exists for properly chosen prime-order elliptic curves.

Q09 Error Analysis

What happens if the calculated shared secrets of Alice and Bob do not match?

Model Answer:

If \(S_A \ne S_B\), key agreement has failed. This indicates one of the following root causes:

  • Active Man-in-the-Middle (MitM) Attack: An adversary intercepted and replaced the transmitted public keys with their own rogue points.
  • Transmission Corruption: Bit errors occurred in the public key coordinates across the network wire.
  • Invalid Curve / Small Subgroup Attack: A party used a point not lying on the curve or lying in a singular / different subgroup.
  • Software / Mathematical Bug: Incorrect modular arithmetic or improper scalar multiplication implementation.

In all such cases, the communication session must be aborted immediately because neither party can establish a mutually intelligible symmetric ciphertext.
